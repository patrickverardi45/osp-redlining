# Product v2 — Permanent Pipeline Contract

> Lane `TRUELINE_PRODUCT_V1_WORKFLOW_SALVAGE_AUDIT`, recorded 2026-06-20. **Architecture/contract only —
> this lane does NOT implement the pipeline.** Derived from [`product_v1_workflow_salvage_audit.md`](product_v1_workflow_salvage_audit.md).
>
> **Generic-names rule (strict):** no customer, project, person, or demo-specific names appear anywhere in
> this contract — entities, fields, states, routes, and artifacts use only generic product terms. A
> concrete deployment binds a real customer/project to the generic `customer_project` entity at runtime;
> it never hardcodes a name into the schema, route, env var, or component.

## Doctrine (non-negotiable invariants)

1. **The v2 engine owns placement truth.** Redline geometry comes only from a reviewed engine
   `redline_manifest` or an explicitly approved human override — never from map snapping or guessing.
2. **AI/OCR output is untrusted until reviewed.** Extraction produces *candidates with provenance +
   confidence*; nothing reaches the engine or an export without passing a review gate.
3. **Bore logs may contain multiple segments / unrelated bores.** The pipeline groups and reviews them
   *before* engine placement, never after.
4. **No faked geometry.** If real geospatial coordinates are unavailable, the system abstains and labels
   the gap; it must never synthesize a KMZ/KML coordinate to fill it.
5. **Exports are reproducible from stored artifacts/manifests.** Any export can be regenerated byte-stable
   from the `artifact_bundle` it was built from.
6. **One authoritative status model.** `closeout_review` and `billing_summary` derive from a single
   persisted status; panels render that status, they never each compute their own.
7. **Strict isolation.** Every entity, route, file, and job is scoped to a `customer_project`; cross-tenant
   access is impossible (the surviving requirement from v1, satisfied by an external auth provider).

## Pipeline overview (generic stages)

```
upload_pipeline → extraction (untrusted) → reviewed_bore_log (grouped + human-reviewed)
   → engine placement (v2 truth) → redline_manifest + artifact_bundle (durable, checksummed)
   → proof_viewer (read-only) → closeout_review (one status) → billing_summary
   → export_package { kmz_export | kml_export | print/save/share } (reproducible)
```

Each arrow is a typed handoff with a stable contract; each stage is independently testable and
re-runnable. No stage mutates a prior stage's stored output.

## Core entities

- **`customer_project`** — the isolation root. `{ id, display_name, created_at }`. All other entities carry
  `customer_project_id`; every route is scoped by it.
- **`processing_job`** — one end-to-end run for a `customer_project`. Carries the lifecycle state (below).
- **`artifact_bundle`** — an immutable, content-addressed set of files (manifests, render PNGs, exports)
  with per-file `sha256` + `bytes`; the unit of durability and reproducibility.
- **`redline_manifest`** — the engine's machine-readable truth: per-log status / provenance / geometry
  references / artifact references. (The v2 engine already emits this — see the engine's
  `redline_manifest` contract; this pipeline consumes it, never reinterprets it.)

## 1. Upload procedure contract

- **Route shape:** `POST /customer_projects/{customer_project_id}/processing_jobs/{job_id}/uploads`
  (auth-gated, `customer_project`-scoped). No global/unscoped upload route exists.
- **Accepted kinds:** `PLAN_PDF`, `BORE_LOG` (CSV/XLSX/PDF), `GIS_ROUTE` (KMZ/KML). Each upload declares its
  `kind`; the server validates type + size and rejects unknown kinds.
- **Persistence:** files land in the durable `artifact_bundle` store under the job (object storage,
  versioned, checksummed) — never local disk globals, never a shared `CURRENT_ROUTE`.
- **Response:** `{ upload_id, kind, sha256, bytes, stored_at, extraction_status: "queued" }`.
- **Isolation assumption made explicit:** the server derives `customer_project_id` from the authenticated
  principal and the path; a mismatch is a 403. Uploads for one project can never touch another's bundle.

## 2. Processing-job lifecycle (state machine)

```
CREATED → UPLOADING → EXTRACTING → AWAITING_REVIEW → PLACING → PLACED
        → CLOSEOUT_REVIEW → CLOSED            (any state → FAILED with reason)
```

- Transitions are server-authoritative and audited (`who`, `when`, `from`, `to`, `reason`).
- `EXTRACTING` produces untrusted candidates only. `AWAITING_REVIEW` blocks the engine until the
  reviewed-bore-log gate passes. `PLACED` means a `redline_manifest` + `artifact_bundle` exist.
- The single `processing_job.status` is the **one authoritative status** that all later panels read.

## 3. Reviewed-bore-log schema concept

The mandatory gate between extraction and placement. Conceptual shape (illustrative, generic):

```jsonc
{
  "bore_log_id": "...",
  "customer_project_id": "...",
  "source_upload_id": "...",
  "extraction": {                      // untrusted, provenance-tagged
    "method": "ocr" | "text_parse",
    "engine": "tesseract" | "pdfplumber" | "...",
    "cells": [ { "field": "station|depth|boc|note",
                 "value": "...", "normalized": "...",
                 "confidence": "high|medium|low",
                 "provenance": { "variant": "...", "config": "...", "normalizer": "..." } } ]
  },
  "segments": [                        // GROUPED before placement
    { "segment_id": "...", "logical_bore_ref": "...",
      "row_range": [start, end], "continuity": "ok|gap|out_of_order",
      "stations": [ ... ] } ],
  "review": {                          // the gate
    "status": "pending|approved|rejected",
    "reviewed_by": "...", "reviewed_at": "...",
    "edits": [ ... ],                  // operator corrections, audited
    "grouping_confirmed": true }
}
```

Rules: low-confidence cells are flagged in the upload/extraction response; `infer`-style station
guesses are *suggestions* surfaced to the reviewer, never silent truth; multi-bore CSVs are segmented
by logical bore (header/ID parse + continuity check) and the **grouping is confirmed by a human before
`PLACING`**. The engine consumes only `review.status == approved` segments.

## 4. Redline-manifest / artifact-bundle handoff

- Placement (the v2 engine) emits a `redline_manifest` (status/provenance/geometry-refs/artifact-refs) and
  writes the final artifacts (render PNGs, etc.) into an immutable `artifact_bundle` (content-addressed id,
  per-file `sha256`+`bytes`, a `latest_valid` pointer).
- Downstream stages (`proof_viewer`, `closeout_review`, exports) consume the manifest **read-only** and
  resolve artifacts by manifest path + `sha256`. They never infer status from filenames or recompute
  geometry.
- This handoff already exists in the engine's durable-bundle contract; this pipeline standardizes it as the
  **only** source of redline geometry for every downstream consumer.

## 5. Closeout-review contract (one status model)

- A single persisted `closeout_review.status` per job: `OPEN → READY_FOR_REVIEW → BLOCKED → LOCKED →
  APPROVED` (server-authoritative, audited). All readiness UI renders *this* value — there is no
  panel-local readiness computation and **no client flag may override it**.
- A gate checklist (design loaded, reviewed bore logs approved, plans attached, review decisions recorded,
  evidence attached, notes present-or-waived, manifest present) is evaluated **server-side**; the result is
  stored, not recomputed per render.
- `LOCKED`/`APPROVED` are permission-gated transitions with audit (`who`/`when`); lock state is durable
  (survives restart), never in-memory.

## 6. Billing-summary contract

- `billing_summary` is computed and persisted **server-side** from authoritative inputs:
  `{ effective_footage, cost_per_unit, base_total, exceptions:[{label, amount, note}], exception_total,
  final_total, derived_at, inputs_hash }`.
- `billing_summary` derives from the same authoritative job status; it is **part of** the closeout status
  model, not a parallel flag. A change to inputs after approval invalidates approval (re-review required).
- The client renders the server-computed totals; it never computes or overrides them.

## 7. KMZ / KML export contract (geometry safety)

- **Source of geometry = the approved `redline_manifest` only** (reviewed engine output or approved human
  override). Never the uploaded GIS file, never route-snapped/street-snapped geometry, never map display
  coordinates.
- **Every coordinate carries** `source` (`engine_reviewed` | `human_override` | `field_gps`) and
  `confidence` (`high|medium|low`). The export declares a **spatial reference header**
  (`{ crs: "EPSG:4326", datum: "WGS84", units: "degrees" }`).
- **Abstain, never fake.** If a redline lacks real geospatial coordinates, the export omits geometry for
  that redline and records an explicit `geometry_unavailable` reason — it must not interpolate or snap a
  placeholder coordinate.
- Uploaded KMZ/KML semantic features (folder/classification/chainage/lifecycle) are **input context only**
  and may be carried as clearly-labeled reference layers, never as the exported redline truth.
- The export is itself an `artifact_bundle` member (checksummed, reproducible from the manifest).

## 8. Print / save / share — `export_package` contract

- An `export_package` is a **stored, versioned, checksummed artifact** (e.g., a closeout packet
  document), generated server-side and resolvable by a stable URL — not an ephemeral browser print.
- Reuse the v1 section structure as a UI/export pattern: job summary, production summary, plan evidence,
  field evidence, exceptions, billing summary, operator notes, gate checklist, QA flags, decision log.
- Embedded evidence uses persistent (not blob) URLs or inlined checksummed assets. The package footer
  records `generated_at`, `generated_by`, and the source `artifact_bundle` id + manifest `sha256` so any
  package is reproducible and auditable.
- Generation requires the job to be at least `READY_FOR_REVIEW`; share/billing-grade packages require
  `APPROVED`.

## Cross-cutting invariants (apply to every stage)

- **Isolation:** `customer_project`-scoped routes/storage; cross-tenant = 403.
- **Untrusted extraction:** provenance + confidence on every extracted value; review gate before use.
- **Geometry safety:** truth from manifest/override only; display snapping is visual-only and warns on
  large residuals; no fake coordinates.
- **Reproducibility:** every export rebuildable byte-stable from its `artifact_bundle`.
- **Single status:** one persisted job/closeout status; panels render it; no client override.
- **Auditability:** every state transition and override records `who`/`when`/`reason`.

## Tests needed before implementation (per capability)

- **Upload:** rejects unknown kinds/oversize; cross-`customer_project` upload → 403; concurrent uploads to
  two jobs never share state; response carries correct `sha256`/`bytes`.
- **Extraction/reviewed-bore-log:** low-confidence cells are flagged, not silently used; a multi-bore CSV
  is segmented by logical bore; engine consumes only `approved` segments; station guesses surface as
  suggestions (assert none enter truth unreviewed).
- **Manifest handoff:** downstream consumers resolve artifacts by path+`sha256`; a tampered/missing artifact
  fails closed; status is never inferred from filenames.
- **Map/proof_viewer:** display snapping never mutates source coordinates; a residual beyond threshold
  produces a warning; the viewer renders manifest geometry, not snapped geometry.
- **KMZ/KML export:** geometry source is the approved manifest (assert it is NOT the uploaded KMZ);
  missing-coordinate redlines are omitted with a reason (assert no synthesized coordinate); export header
  declares CRS; export is byte-reproducible from the bundle.
- **Closeout/billing:** one status model — assert all panels agree; no client flag overrides server status;
  `billing_summary` recomputation invalidates a prior approval; lock state survives a restart.
- **Export_package:** generated server-side, checksummed, reproducible; gated on job status; embedded
  evidence uses persistent URLs.
